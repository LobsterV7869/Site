Privacy Policy

Last updated: October 9, 2026

This Privacy Policy explains how the operator of Lobster (“Lobster,” “we,” or “us”) handles information when you use the Lobster Discord bot. Lobster is a Discord bot for server setup, moderation, welcome and farewell messages, tickets, giveaways, utilities, and chat levels. This policy covers Lobster’s handling of information; Discord independently handles information under its own policies.

1. Information Lobster processes

Lobster receives information from Discord when it is installed in a server or used. Depending on enabled features and commands, this may include:

  • Discord user, server, channel, role, message, and interaction identifiers, and basic Discord account or server details needed to run a requested command or feature.
  • If you sign in to the optional web dashboard: your Discord user ID, username, avatar, the servers you belong to, and the server permissions Discord reports for your account. Lobster uses these details to show servers where you can manage the bot.
  • When you authorize the dashboard, Discord OAuth access and refresh tokens are held temporarily in the bot process so it can confirm your identity and server permissions. After a one-use sign-in handoff, the dashboard keeps a signed, opaque session token in browser local storage for up to seven days; it does not ask for or receive your Discord password or Discord OAuth tokens.
  • Server configuration, such as selected channels and roles, verification settings, welcome/farewell settings, AutoMod rules and blocked words, ticket-panel settings, logging preferences, reaction-role mappings, and auto-reply triggers and responses.
  • Member identifiers and feature data, including AFK reasons and timestamps, giveaway entries, and chat XP and level timestamps.
  • Message text while it is processed to handle commands, configured auto-replies, counting, or enabled AutoMod filters. AutoMod may temporarily keep message hashes and timestamps in memory to detect duplicates or message floods.
  • If a server administrator explicitly enables automatic backups with /backup enable or requests a one-off snapshot with /backup create, Lobster saves message text and metadata from accessible text channels and active threads, along with server role and channel settings. Backups are disabled by default.
  • When a server administrator enables ticket transcripts, message text, attachment URLs, timestamps, and author names from a closed ticket are collected to generate a transcript. This transcript is posted as a file to the administrator-selected transcript channel in Discord; it is not saved in Lobster’s local database.

2. How information is used

Lobster uses this information only to provide and maintain its features: authenticate dashboard users; confirm server-management permissions; display available server settings and roles; apply dashboard changes requested by authorized administrators; respond to commands and interactions; apply server-configured moderation and Discord-native button verification; manage roles, tickets, giveaways, and levels; send configured messages; and report server events to channels selected by the server’s administrators. Verification assigns or removes server roles based on a member pressing the Discord button; it does not establish real-world identity or verify an external account. Discord may record role changes in its own audit log. Event logs sent by Lobster may identify a member or channel and describe an event, but Lobster’s message edit and deletion logs do not include message contents.

Lobster does not record voice conversations. A voice connection feature may connect the bot to a voice channel when requested, but the bot does not record or store audio.

3. Storage and retention

The bot instance stores operational settings and records in a local data/database.json file on the machine where Lobster is hosted. This includes server configuration, backup opt-in settings, giveaway records and participant IDs, AFK records, level data, auto-replies, and reaction-role mappings. The file may remain on that machine while the bot is running and until its operator deletes it. Lobster has no automatic, fixed deletion schedule for all stored records.

When an administrator enables automatic backups, Lobster creates a compressed snapshot immediately and refreshes it every three days. The first snapshot includes messages from the preceding three days; later snapshots include messages created since the previous successful snapshot, along with the current roles and channel settings. An administrator can also create a one-off snapshot with /backup create. Snapshots include message content, author IDs and names, timestamps, attachment names and URLs, and embed data. Attachment files themselves are not copied, and attachment URLs may expire. A snapshot is limited to 10,000 messages; if that limit is exceeded or Lobster cannot read a channel's history, the new snapshot fails and the previous successful backup is kept. On success, the new snapshot replaces the previous one, so only the newest backup is retained in the local data/backups/ folder until another successful snapshot replaces it or the bot operator deletes it. Administrators can download it using /backup export or stop future automatic backups using /backup disable; disabling does not delete the existing snapshot. These archives do not restore messages as if they were authored by their original users.

Some temporary moderation data is held in memory and is discarded as it ages out or when the bot process stops. Ticket transcripts are retained in Discord according to the server’s own channel and message management; server administrators control access to and deletion of those transcripts. Discord may separately retain its own data.

Discord OAuth tokens and dashboard sessions are held in the bot process’s memory, not in data/database.json. The one-use sign-in handoff expires after one minute. Dashboard sessions expire after seven days and are removed when you sign out, the session expires, or the bot restarts. The signed session token remains in browser local storage until sign-out or expiry, but becomes invalid after a bot restart, when you will need to sign in again.

The operator should restrict access to the bot host and its database and credentials. Do not expose the database file or bot configuration publicly.

4. Sharing and service providers

We do not sell personal information. Lobster communicates with Discord to provide bot features and dashboard sign-in. Information is sent to Discord channels or users when a feature is configured to do so—for example, welcome messages, moderation notices, server logs, giveaway announcements, and optional ticket transcripts. When an administrator uses /backup export, the selected backup is uploaded to Discord as an ephemeral attachment visible to that administrator; Discord may process it under its own terms. The static dashboard host may process ordinary web request data, and the bot operator’s hosting provider may process information needed to run the bot. Discord and hosting providers process information under their own terms and privacy policies.

5. Your choices and deletion requests

Server administrators can disable optional features, change the channels where bot output is sent, turn off ticket transcripts, and remove Lobster from a server. Dashboard users can sign out to clear their active dashboard session. Removing the bot does not automatically erase the local database file or information already sent to Discord. The bot operator can delete the local database file to remove Lobster’s locally stored records, but this also removes settings for all servers on that bot instance. For requests about information held by the operator, contact the Lobster team through the support Discord and include the server and relevant Discord user ID; do not send passwords or bot tokens. Requests concerning data held by Discord must be made to Discord.

6. Children

Lobster is intended for use within Discord and is not designed to collect information directly from children. Users must meet Discord’s minimum age requirements and any higher age requirement that applies where they live.

7. Changes and contact

We may update this policy when Lobster’s features or data handling change. The “Last updated” date above indicates the latest revision. Continued use after an update means this policy applies to subsequent use, subject to applicable law.
